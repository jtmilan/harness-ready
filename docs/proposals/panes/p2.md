## Mandate (applies to every proposal)

**LIVING / CRAFTED:** instrumentation for people who live in terminals — a command center that is *running*, not a marketing page. Layered ambient background (faint technical grid / scanline / topographic contour / slow telemetry field — **not** aurora blobs). Live micro-interactions (hover/press/focus on panes, buttons, queue rows, harness tiles; FLIP when roster/queue reorders; purposeful chart updates). Strong type contrast: monospace/technical **DISPLAY** for headers/labels/metrics + readable **body** face. Open each surface with what is most characteristic of fleet control (live queue / fleet / terminals), never a generic hero. All motion honors `prefers-reduced-motion`.

**AVOID (hard):** centered hero trio; row of 3–4 equal feature cards; gradient headlines; indigo/violet/pink gradients; site-wide glassmorphism; blanket `rounded-2xl`; aurora blobs; cream/beige/terracotta/serif; near-black + single neon accent; dense broadsheet hairline grids.

**Navigation:** no new top-bar clutter — new actions → palette or `⋯` overflow (topbar-dedupe bar).  
**Pause/resume:** RESUME-always, never a pause toggle (no `paused` field; HANDOFF + DB §6).  
**R3:** every control names its backing bridge method/state or is tagged **NEEDS-BACKEND**.

**shadcn primitives (DB §9):** segmented control, chip, dialog/sheet, tooltip, badge, tabs — named per proposal below.

# 5 · Attention / queue semantics + per-pane inline reply

**Target (HANDOFF + DB §6):** ranked who-needs-you; amber = single needs-you signal; RESUME-always; inline reply on pane.

### Ranking (HANDOFF + task refinement)

Suggested sort (backend emits order via `subscribe`; UI preserves):

1. **needs_human / `needs_input` first** (base ~300 + wait seconds)  
2. Then by severity among non-needs: **error** (400) still tops pure working — *task says:* needs_human first → **turn_end > rate_limit** → longest wait  
3. Interpret operational attention reasons: prefer explicit `attention.reason` classes when present (`needs_input`, turn_end, rate_limit, blocked, error)  
4. **Longest wait** (`attention.since`) breaks ties  

**Refined rank key (document for implementers):**  
`primary = needs_input/needs_human → 0; error → 1; blocked → 2; rate_limit → 3; turn_end → 4; other attention → 5; working/idle → 9`  
then `+ secondsWaiting` within band — *or* keep HANDOFF numeric scores but **surface needs_input above error only if product wants human-questions first**; task text prioritizes **needs_human first**. This proposal **follows the task**: needs_human first, then turn_end > rate_limit, then longest wait; map error/blocked as interruptive peers with icons so nothing silent-fails.

**Practical compromise (honest):**  
- Strip section **A — Needs you** (`needs_input`): amber, inline reply  
- Section **B — Faults** (`error`, `blocked`): danger/blocked badges, RESUME/restart actions  
- Section **C — Waiting** (rate_limit, turn_end): muted, longest wait first  

Amber **only** for needs-you (section A). Faults use danger/blocked lanes — not amber (semantic lanes sacred).

### Living open
