## R-OBS — Real fleet monitoring (MAKE-REAL)

### F-OBS-1 · Per-agent real-signal health table (Monitoring primary surface)

- **id:** F-OBS-1  
- **title:** Replace simulated Monitoring with per-agent real-signal health table  
- **implements:** PRD §7 R-OBS AC; DESIGN-BRIEF §4.2; BUILD-PLAN Phase 1a/1b; R4  
- **icp_fit:** Power operators need honest per-pane health under load, not a vanity fleet chart — **MAKE-REAL** (BridgeMind has no fleet telemetry).  
- **ux:**  
  - **Screen:** MONITORING tab (`Monitoring.jsx`) becomes the primary surface: a dense table/strip, one row per live pane from `bridge.subscribe`, columns bound to the real-signal list — process liveness · per-child CPU · per-child mem · git state (branch/dirty) · last-tool-failure · human-gate queue depth (attention rank / seconds waiting).  
  - **Interaction:** click row → focus/zoom that pane on COMMAND (existing zoom handler); hover → tooltip with raw sample + last-event timestamp.  
  - **States covered:**  
    | State | Rendering |  
    |---|---|  
    | **empty** | fleet size 0 — "no agents · spawn from COMMAND"; no charts, no fake AGENT-001 rows |  
    | **loading** | first subscribe not yet arrived — skeleton rows, badge `loading` |  
    | **stale** | sample age > threshold (e.g. 5s) — badge `stale · Ns`, series freezes, no interpolation |  
    | **state_blind** | harness cannot yield hook telemetry (CommandCode/Pi/Grok per harness descriptors) — cell shows `telemetry limited`, never a fake curve |  
    | **needs-human** | `status === needs_input` — amber lane + reason string from `attention` |  
    | **error** | `status === error` — danger lane + last failure text |  
  - Explicitly **no** vanity aggregate-only dashboard as the hero; aggregates (if any) are secondary and must inherit source/age.  
- **backend_dep:**  
  - EXISTS: `bridge.subscribe` (agent snapshot: id, kind, role, branch, worktree, status, attention, output)  
  - NEEDS-BACKEND: per-child CPU/mem samples; git dirty/state query; last-tool-failure event; human-gate queue depth as first-class metric (P0-ALIGNMENT §2). Propose signatures only (R10):  
    - `getAgentMetrics(): Promise<Array<{id, cpuPct, memBytes, sampledAt}>>` or extend subscribe payload  
    - `getGitState(id)` or field on snapshot: `{branch, dirty, ahead, behind}`  
    - `lastToolFailure: {tool, message, at} | null` on snapshot  
    - queue depth already partially derivable from attention/status ranking — formalize as `gateQueueDepth` when R-GATES stabilizes  
- **fake_affordance_check:** PASS — strip `monitorData.js` random-walk from live path; until metrics land, cells render `no data` (not zero). Demo fixture only behind an explicit labelled path if kept.  
- **components:** `Table` / dense list, `Badge`, `Tooltip`, `Skeleton`; shadcn primitives already in ui/  
- **visual:** lanes `--need` (needs-human) · `--success` (working healthy) · `--danger` (error) · `--info` (live sample age); tabular numerals for CPU/mem; small-caps column headers; source/age chip per section  
- **effort:** M  
- **priority:** P0  
- **a11y_keyboard:** row focusable; Enter focuses pane; tooltip content in aria-describedby; status never color-only (icon + label); `prefers-reduced-motion` freezes chart motion if charts remain secondary
