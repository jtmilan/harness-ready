## 1 · Token system

### 1.1 Architecture

Three layers. Brand/skin may recolor **surfaces and brand accent**; lanes are **sacred** and sit outside brand override.

```
html[data-skin="…"]   ← optional future; not built now
  └─ surface + brand tokens (background, card, primary/brand accent, borders, muted)
:root / .dark           ← app theme (default = dark terminal)
  └─ shadcn HSL channels (background, foreground, primary, destructive, ring, chart-*, radius)
.semantic-lanes         ← ALWAYS defined; no skin rewrite
  └─ --need, --success, --danger, --info  (+ -fg, -muted, -border companions)
motion / density / type / ambient  ← independent of skin
```

**Format convention:** keep shadcn’s space-separated HSL *channels* (no `hsl()` wrapper) so existing `hsl(var(--background))` Tailwind mappings keep working. Lanes follow the same channel form; components consume via Tailwind extend or `hsl(var(--need))`.

### 1.5 `data-skin`-ready layer (token-ready now, switcher later)

## 2 · Typography

### 2.1 Pairing (keep, discipline)

| Role | Face | Token | Weight | Use |
|---|---|---|---|---|
| **Display** | Rajdhani | `--font-display` / `font-display` | 600–700 | page titles, section headers, KPI labels (uppercase tracking) |
| **Heading** | Rajdhani | `--font-heading` | 600–700 | panel titles (“FLEET RESOURCE USAGE”) |
| **Body / UI mono** | JetBrains Mono | `--font-body`, `--font-mono` | 400 / 700 | body copy, command motifs, tooltips, axis ticks, values |

**Do not** introduce Inter / Geist / Roboto / Arial as a third family. **Do not** introduce serif or cream/terracotta editorial type (AVOID list).

### 2.2 Type scale (bold ratios)

Instrument panels need *contrast between layers*, not a marketing modular scale.

| Step | Size | Face | Tracking | Transform / variant | Example |
|---|---|---|---|---|---|
| `display-hero` | 2.25–3rem (36–48px) | display 700 | `0.2–0.3em` | uppercase | “AGENT COMMAND CENTER” (empty-state only; not a centered marketing hero trio) |
| `display-panel` | 0.875rem (14px) | heading 700 | `0.2em` | uppercase | chart / card panel titles |
| `label-section` | 0.6875–0.75rem (11–12px) | heading 700 | `0.3–0.35em` | uppercase + `font-variant: small-caps` *or* full uppercase tracking (pick one system-wide — prefer tracking uppercase for mono cohesion) | “SUPPORTED HARNESSES”, “SELECT WORKSPACE” |
| `label-meta` | 0.625–0.6875rem (10–11px) | mono 400 | normal / slight | muted-foreground | axis ticks, “avg across agents”, `$ cmd` |
| `metric-lg` | 1.875–2.25rem (30–36px) | mono 700 | tight (0) | **`font-variant-numeric: tabular-nums`** | StatCard value |
| `metric-md` | 1–1.25rem | mono 700 | 0 | tabular-nums | inline counters, badge counts |
| `body` | 0.8125–0.875rem (13–14px) | mono 400 | 0 | normal | empty-state description, form fields |
| `cmd` | 0.75rem | mono 400 | 0 | muted info | `$ agent fleet status — N active` |

**Mandatory:** every numeric metric (KPI values, chart tooltips, success %, CPU/mem, task counts, capacity) uses `tabular-nums` so digits do not jitter on live update.

### 2.3 Small-caps section labels

Spec: section labels use `font-heading` + uppercase + wide tracking (`0.3em+`) + lane-or-muted color (`text-muted-foreground` or `text-info` at reduced emphasis). If CSS `font-variant: small-caps` is applied, still keep tracking moderate — Rajdhani small-caps can look sparse; **uppercase tracked labels are the screenshot-proven pattern** and remain preferred.

### 2.4 Command-line motif

Preserve `$ …` as first-class typography:

- Empty fleet status line
- Harness tile secondary line (`$ claude` / `$ cursor` / …)
- Future palette rows may show shell-like prefixes

Color: `text-muted-foreground` or `info` at ~60% emphasis — never pure brand glow on every `$`.

## 3 · Density + spacing

### 3.1 Philosophy

Control-dense terminal instrument panel — **not** marketing whitespace. Prefer information per viewport over generous card air. Keep the command line and top-bar actions tight; monitoring is a dashboard of *signals*, not a feature gallery.

### 3.2 Spacing scale (4px base)

| Token | Value | Use |
|---|---|---|
| `--space-0` | 0 | |
| `--space-1` | 4px | icon gaps, tight chip padding |
| `--space-2` | 8px | harness tile pad, compact stack |
| `--space-3` | 12px | default control pad (py-2.5 / px-3 territory) |
| `--space-4` | 16px | StatCard padding, chart inner pad |
| `--space-5` | 20px | page gutter (`p-5` today) — **max default page pad** |
| `--space-6` | 24px | section separation (use sparingly) |
| `--space-8` | 32px | empty-state block gaps only |

**Grid gaps:** KPI row `gap-3`–`gap-4` (12–16px); chart pair `gap-4`–`gap-5`; harness grid `gap-2` (dense). Do not open `gap-8` marketing stacks.

### 3.3 Component density rules

| Surface | Density rule |
|---|---|
| Top bar | existing consolidation bar (primaries + `⋯`); no new permanent controls |
| StatCard | single padding tier (`p-4`); value dominates; subline one row |
| Charts | header strip `py-2.5`; plot `h-72` ok; no decorative empty chrome |
| Harness tiles | compact `px-3 py-2.5`; 2×4 / 4-col grid; square-ish, not hero cards |
| Empty state | centered *command* composition is OK; **avoid** centered hero trio (headline + subtitle + single CTA only). Keep multi-action row + workspace + harness grid as operational content |
| Forms / overlays | mono inputs, 8–12px pad, 1px borders |

### 3.4 Radius + borders

- Default radius: **2px** (`--radius: 0.125rem`) — sharp terminal panels.
- Borders: 1px `border` / lane-border; selected/attention may use 2px lane edge (amber needs_input already uses amber border).
- **Forbidden as default:** `rounded-2xl`, heavy blur glassmorphism, thick soft shadows. Subtle cyan glow on primary CTA is allowed (already in empty-state spawn button) if it uses `--info` alpha, not a multi-stop gradient headline.

### 3.5 Elevation

Prefer **edge + fill** over drop shadow:

1. `background` (page)
2. `card` (panel)
3. `muted` (header strip inside panel)
4. 1px `border` separation

Inset CRT shadow may remain on terminal panes only (`.crt-screen`), not on every card.

## 4 · Motion rules

### 4.1 Motion tokens

| Token | Value | Use |
|---|---|---|
| `--motion-instant` | 0ms | reduced-motion fallback target |
| `--motion-fast` | 100ms | hover color, border, opacity |
| `--motion-base` | 160ms | press, focus ring settle, button bg |
| `--motion-moderate` | 220ms | panel enter, overlay fade |
| `--motion-slow` | 320ms | FLIP roster reorder, chart series morph |
| `--ease-standard` | `cubic-bezier(0.2, 0.0, 0, 1)` | most UI |
| `--ease-emphasize` | `cubic-bezier(0.3, 0.0, 0.2, 1)` | FLIP / layout |
| `--ease-exit` | `cubic-bezier(0.3, 0, 1, 1)` | dismiss |

### 4.2 What moves (purposeful only)

| Interaction | Motion | Notes |
|---|---|---|
| Hover control / harness tile / queue row | border + fg color `--motion-fast` | no scale bounce |
| Press | opacity or bg wash `--motion-fast` | |
| Focus | ring appear `--motion-fast` | visible, not animated blur |
| Roster / queue reorder | FLIP `--motion-slow` + `--ease-emphasize` | only when order actually changes |
| Chart live update | prefer **data join without entrance bounce**; if tweening, ≤ `--motion-slow` and **off under reduced-motion** | ResourceChart already `isAnimationActive={false}` — keep default off for live series |
| Empty-state caret blink | `animate-pulse` ok | disable under reduced-motion |
| Scanline ambient | static preferred; if drift, ≤ 0.5% opacity shift, multi-second period | never aurora |

### 4.3 Reduced-motion off-switch (mandatory)

```css
/* illustrative policy */
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

Also: chart tweens off; FLIP off (instant reorder); caret static or opacity step once; no continuous ambient animation.

### 4.4 Forbidden motion

- Gratuitous page-load hero animations
- Bouncy spring on every tile
- Shimmer skeletons that look like live metrics (honesty: use explicit “loading” copy)
- Gradient text animation / aurora drift

## 5 · Ambient / background layer

### 5.1 Intent

A living instrument field — faint technical texture that reads “this is running hardware/software,” **not** decorative AI-product atmosphere.

### 5.2 Tokens

|---|---|---|
| `--ambient-scanline` | repeating horizontal line color | `187 100% 50%` / alpha ~0.025 (today’s cyan scanline) |

2. **Optional grid** — `::before` on shell, `pointer-events: none`, z low
3. **Content**
4. **Scanlines** — extend existing `.scanlines::after` (z-40, non-interactive); **recolor via `hsl(var(--ambient-scanline) / 0.025)`** instead of raw `rgba(0,229,255,…)`

## 6 · Accessibility pass

### 6.1 Focus rings (system)

| Token / rule | Spec |
|---|---|
| Visible ring | 2px solid `hsl(var(--ring))` + 2px offset against `background` |
| High-contrast fallback | if ring on cyan wash, use `outline: 2px solid hsl(var(--foreground))` |
| Tailwind | `:focus-visible:ring-2 :focus-visible:ring-ring :focus-visible:ring-offset-2 :focus-visible:ring-offset-background` |
| Kill | `focus:outline-none` **without** a `:focus-visible` replacement (AttentionPrompt / form inputs today often outline-none + border change only — border-change may remain *in addition to* ring, not instead of it for keyboard users) |
| Mouse vs keyboard | prefer `:focus-visible` so mouse clicks do not flash rings everywhere |

### 6.2 Contrast (AA targets)

| Pairing | Target | Guidance |
|---|---|---|
| Body text on `background` / `card` | ≥ 4.5:1 | `foreground` / `muted-foreground` tuned so muted still ≥ 4.5 for essential labels; decorative `$` chrome may sit at 3:1 only if not sole information |
| Metric numbers | ≥ 4.5:1 | lane-colored metrics on `card` — verify amber/cyan on dark |
| Icons + labels | icon alone insufficient | |
| Borders as structure | do not rely on 1px low-contrast border alone for state | pair with text/icon |

**Lane-on-dark check (spec intent):** need/success/danger/info at proposed lightness sit in the 50–56% L range on ~7% L backgrounds — should clear AA for large text (metrics) and icons; validate in P5 with a contrast audit before shipping.

### 6.3 Color never sole signal

| State | Color lane | Required companion |
|---|---|---|
| needs_input / attention | `--need` | amber border **+** “NEEDS INPUT” / reply affordance (exists) |
| success | `--success` | ✓ / “SUCCESS” / count |
| error | `--danger` | ✕ / “ERROR” / badge letter already used on panes — keep letter **and** improve non-color for color-blind |
| info / live | `--info` | “LIVE · Ns” text or “CPU” legend — never cyan alone |
| stale / placeholder | muted + dashed | explicit “PLACEHOLDER” / “STALE” / “NO DATA” badge (R4) |
| state_blind | muted | “telemetry limited” caption |

**Monitoring charts:** every series in legend with name; tooltip includes series name + value + unit; bar colors paired with threshold label in tooltip (`SUCCESS 92%` not just a green bar).

### 6.4 Keyboard (visual system scope)

Visual system does not invent new shortcuts (that is P1/P2), but every restyled control must:

- Be focusable in tab order if it is a button/link/control  
- Show the focus ring system above  
- Not use color-only hover as the only affordance (border or underline too)

### 6.5 Motion a11y

See §4.3 `prefers-reduced-motion`.
